# ADR 0004: walk-up 边界锚定 ctx.cwd

- 状态：已接受
- 日期：2026-10-14

## 上下文

walkup 动作从被操作文件向上收集上下文文件，需要一个停止边界。pi-rules 锚定 repo root（做项目根检测）；pi-cues 刻意不做 repo root 检测。最初设计锚定**配置文件所在目录**。

## 决策

边界锚定 `ctx.cwd`（会话工作目录）。被操作文件不在 cwd 子树下时**不触发**（早期版本回退检查 cwd 本身，已移除——无关路径不该拉来无关上下文）。

## 备选

- **锚定配置目录**：与 Q1 选定的 `.pi/pi-cues.toml` 布局冲突——配置目录是 `.pi/`，项目根的 AGENTS.md 永远在边界外；全局配置更糟，锚点落在 `~/.pi/agent`，对任何项目文件都在子树外。核心用例整体失效。
- **锚定 `.pi/` 的父目录**：结果正确但规则隐晦，不同配置路径形态父级语义不一致。
- **repo root 检测**：引入 git/jj 探测复杂度，收益不明确；真有 monorepo 跨仓库需求再评估。

## 后果

cwd 对全局/项目配置语义一致，且与路径匹配的 projectRelative base 同一基准。代价：cwd 不是项目根的会话（如在子目录启动 pi），walk-up 收集不到上层目录的上下文文件。
