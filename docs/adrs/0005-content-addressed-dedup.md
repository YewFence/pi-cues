# ADR 0005: 按内容寻址的会话去重

- 状态：已接受
- 日期：2026-10-14

## 上下文

会话级去重的 key 怎么选。最初 walkup 的键是「anchor + 文件名列表排序」——嵌入了配置形式。引入内置默认 walkup 时暴露问题：默认 `[AGENTS.md]` 与用户自定义 `["AGENTS.md", "CONTEXT.md"]` 是两个键，AGENTS.md 会被注入两次。

## 决策

所有 action 的去重键**按内容寻址、与配置形式无关**：`file` 用解析后的绝对路径，`skill` 用 skill 名，`walkup` 用收集到的每个上下文文件的 realPath。块级（anchor, names）claim 删除。

## 备选

- **保留块级键 + 默认值特例**：默认与用户 walkup 合并去重需要额外机制，治标不治本。
- **保留块级键 + 不给默认值**：放弃零配置价值。

## 后果

两个正确的语义随之自然成立：什么都没找到就什么都不记，后续事件自然重试（删掉"没找到不占位"的补丁）；会话后期首次进入的目录仍能加载其中的上下文文件（对齐 pi-rules dynamic 语义）。代价：walkup 在每次路径事件都要过一遍收集——由会话态发现缓存（stat 指纹）压住成本。
